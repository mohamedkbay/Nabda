PrinciplesCreate messageResourcesErrors

Designed for integration

Small surface. Explicit behavior.

Every request is JSON, every protected endpoint uses an organization API key, and every error returns a stable code with a request identifier.

Authentication

Bearer API keys

Send the key in Authorization. Store it like a password and never expose it in browser code or logs.

Reliability

Idempotency-Key

A unique 16–128 character key protects message creation from accidental duplicates during client retries.

Isolation

Organization scopes

Records and permissions are resolved from the authenticated key, not from a caller-provided organization ID.

Core request

Create a message

The API validates the E.164 destination, content, declared purpose and consent, optional schedule, plan quota, rate limit, device ownership, and opt-out status before accepting the request.

POST/v1/messages

Required headers

HeaderValue
AuthorizationBearer nbda_test_…
Content-Typeapplication/json
Idempotency-Key16–128 safe ASCII characters; unique per intended message

Accepted response

A 202 response means the message was recorded and queued. It does not mean the carrier delivered it. An exact replay returns 200 and the original message.

Error model

Errors tell the client what to do next.

401 invalid_api_key

The key is missing, malformed, revoked, expired, or unknown. Do not retry until credentials are corrected.

422 validation_error

One or more request fields failed validation. Correct the fields before retrying.

429 rate_limited

The organization exceeded a request or plan limit. Respect Retry-After and inspect usage.
