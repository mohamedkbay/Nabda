STATUS / LOCAL CLIENT

Desktop polls status; it does not expose a webhook receiver.

A local application normally has no stable public HTTPS callback URL. Phase one reads message state from the hosted provider API instead of opening an inbound port.

Current behavior

Desktop polls GET /v1/messages/:id at the interval selected in Integration settings.

Provider webhooks

httpSMS can send events to a separate public HTTPS service configured with the provider.

Future option

A companion server may receive signed events later, but it is not required or bundled.

Do not expose Desktop through tunnels or port forwarding. Use a dedicated public service and follow the provider's current signature guidance.

Need real-time event delivery?

Review the official webhook documentation before building a receiver.
