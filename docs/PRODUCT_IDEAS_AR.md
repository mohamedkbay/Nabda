# أفكار المنتج — نبضة API SaaS

هذا الملف يجمع أفكار التطوير بعد المرحلة الأولى. ترتيبها يحافظ على كون نبضة منصة رسائل معاملات متوقعة ومصرحًا بها، وليس أداة للرسائل الإعلانية غير المرغوبة.

## نُفّذ في المرحلة الحالية

- طابور دائم: PostgreSQL هو مصدر الحقيقة وBullMQ ينفذ المهام، مع جدولة، idempotency، وحد إرسال لكل مؤسسة.
- جهات اتصال معزولة لكل مؤسسة: اسم، رقم E.164، tags، مرجع موافقة، وmetadata محدودة.
- تنظيف تلقائي آمن: يحجب محتوى الرسائل القديمة حسب مدة احتفاظ الخطة، مع إبقاء الحالة والتوقيت وسجل التدقيق وopt-out.
- قائمة إيقاف يعاد فحصها عند قبول الطلب وقبل اتصال العامل بالمزود.
- حالات الرسالة، ملخص الاستخدام، أحداث، وWebhooks موقعة.

## الأولوية التالية

### لوحة تشغيل حقيقية

- قائمة رسائل قابلة للبحث والتصفية حسب الحالة والجهاز والتاريخ.
- شاشة Queue تعرض الجاهز والمجدول وقيد التنفيذ وحالات المراجعة اليدوية.
- شاشة تفاصيل الرسالة مع timeline للأحداث دون كشف بيانات المزود السرية.
- إعادة تشغيل Webhook فاشل يدويًا مع سجل المحاولات.

### إدارة جهات الاتصال

- استيراد CSV مع preview وإزالة التكرار قبل الحفظ.
- مجموعات وtags وقوائم ذكية، مع حد أقصى حسب الخطة.
- سجل موافقة مستقل يوضح المصدر والوقت والسياسة المستخدمة.
- تصدير جهات الاتصال وحذفها أو إخفاء بياناتها وفق سياسة الخصوصية.

### الأجهزة

- onboarding آمن لهاتف Android عبر رمز قصير أو QR مؤقت.
- heartbeat وحالة الاتصال والبطارية والشريحة وآخر ظهور.
- اختيار SIM والجهاز عند وجود أكثر من هاتف، مع فاصل إرسال مستقل لكل جهاز.
- تعطيل الجهاز أو تدوير credential دون تغيير مفاتيح عملاء API.

### القوالب والمطورون

- قوالب معاملات versioned بمتغيرات محددة والتحقق من طول الرسالة بعد الدمج.
- بيئتا Sandbox وLive بمفاتيح منفصلة وحدود منفصلة.
- OpenAPI، SDKs صغيرة لـNode/PHP/Python، وأمثلة Webhook verification.
- صفحة status وrequest IDs وسجل أخطاء منقح لا يحتوي نص الرسالة أو الأسرار.

## أفكار تجارية وتشغيلية

- خطط مبنية على استخدام المنصة، عدد الأجهزة، retention، وWebhooks؛ لا وعد برسائل غير محدودة.
- تنبيهات عند 70% و90% و100% من الحصة.
- أدوار owner/admin/developer/support وموافقة ثنائية على العمليات الحساسة.
- فواتير واشتراكات مع grace period واضح وتعطيل منضبط بدل فقد الرسائل.
- تقارير تسليم مجمعة لا تعرض بيانات شخصية أكثر من اللازم.

## ضوابط لا نتجاوزها

- لا bulk endpoint يتجاوز الحصة أو opt-out أو فحص الموافقة.
- لا إعادة تلقائية عندما تكون نتيجة اتصال المزود غير مؤكدة؛ تتحول الرسالة إلى مراجعة يدوية.
- لا حفظ دائم لمحتوى الرسالة بعد انتهاء retention، بينما تبقى قائمة الإيقاف وسجلات التدقيق اللازمة.
- لا مفاتيح مزود أو أرقام مرسل ثابتة داخل الكود أو واجهة العميل.
- لا رسائل تسويقية دون موافقة قابلة للإثبات، ولا أدوات لتجاوز حدود الشبكات أو مكافحة الإساءة.
