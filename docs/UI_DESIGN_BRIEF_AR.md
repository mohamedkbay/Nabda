# مرجع تصميم الموقع ومركز المساعدة — نبضة

الحالة: منفذ في الموقع المحلي متعدد الصفحات.

آخر تحديث: 2026-08-30

## نطاق المرجع

تُعامل الصورة والمقاطع الخمسة التي قدمها صاحب المشروع كمرجع لاتجاه الموقع العام، وتُعامل لقطة التوثيق اللاحقة كمرجع لبنية مركز المساعدة. المطلوب هو الحفاظ على الإيقاع البصري، الشبكة، الهدوء، وبنية التصفح، مع استبدال كل اسم ومحتوى وأيقونة تخص المنتجات الظاهرة في المراجع بهوية «نبضة» ووظائفها الفعلية.

لا تعني كلمة «نفس» نسخ النصوص أو العلامة الخارجية. لا يظهر اسم أو شعار المزود الخارجي كعلامة للمنتج، ولا تُعرض أرقام هواتف أو مفاتيح حقيقية في الرسومات التجريبية.

## الاتجاه العام

- الإنجليزية هي اللغة الرئيسية وLTR هو الاتجاه الافتراضي. العربية ترجمة اختيارية كاملة تبدّل الصفحة إلى RTL وتحفظ التفضيل محليًا.
- الصفحة ثابتة؛ الحركة محصورة داخل الرسومات التوضيحية للبطاقات.
- لا gradients صاخبة، ولا زجاج مبالغ فيه، ولا ظلال ثقيلة.
- الشكل هندسي حديث: حدود رفيعة، زوايا هادئة، ونص أسود دافئ.
- يستخدم الموقع خط Cairo Variable مستضافًا محليًا للإنجليزية والعربية، دون CDN.
- تستخدم البيانات المعروضة أمثلة شكلية فقط، مع حالات الرسائل الفعلية في نبضة.

## رموز التصميم الأولية

القيم التالية مستخرجة بصريًا من المرجع، وتُضبط نهائيًا بعد تنفيذ أول نموذج في المتصفح:

```css
:root {
  --page: #f4f6f3;
  --surface: #ffffff;
  --surface-strong: #ffffff;
  --ink: #111411;
  --muted: #5f675f;
  --line: #dce2dc;
  --line-soft: #ecefeb;
  --accent: #146b4a;
  --success: #0b5136;
  --success-soft: #dff4e9;
  --radius-card: 18px;
  --radius-item: 12px;
  --grid-gap: 16px;
}
```

- الخط المعتمد: `Cairo Variable` بأصول WOFF2 محلية، ثم `Cairo` و`system-ui` كبدائل.
- العنوان الرئيسي على سطح مكتب 1600px: قرابة `42px/1.18` ووزن `600–650`.
- عنوان البطاقة: `27–28px`، والنص الوصفي: `17–18px/1.45`.
- padding البطاقة على سطح المكتب: `32–34px`.
- border: `1px solid var(--line)`، والظلال داخل الرسومات فقط وبشفافية منخفضة.

## التكوين

عند عرض قريب من 1600px تكون الحاوية بعرض يقارب 1000px ومتمركزة. يسبق الشبكة eyebrow صغير ثم عنوان من سطرين ومسافة تقارب 78px.

تستخدم الشبكة عمودين بنسبة تقريبية `7fr 5fr`، بارتفاع موحد للبطاقات يقارب 390px:

```text
┌──────────────────────────┬───────────────────┐
│ واجهات API واضحة وبسيطة │ لوحة الرسائل      │
├───────────────────┬──────┴───────────────────┤
│ ربط هاتف Android │ Webhooks جاهزة للاستخدام │
└───────────────────┴──────────────────────────┘
```

في RTL تكون البطاقة العريضة الأولى على اليمين، ثم ينعكس توزيع العرض في الصف الثاني. كل بطاقة تستخدم `overflow: hidden`، ولا تخرج الحركة عن حدودها.

النص المقترح للقسم:

- eyebrow: `التكامل`
- العنوان: `اربط نبضة بطريقتك.` ثم `API، هاتف Android، أو لوحة التحكم.`

## محتوى البطاقات وحركتها

### 1. واجهات API واضحة وبسيطة

- وصف مقترح: `واجهة موثقة، وضع تجريبي آمن، ومفتاح منفصل لكل مؤسسة.`
- رسم SVG بخطوط دوائر باهتة تتجه إلى شريحة مركزية تحمل اسم «نبضة» فقط.
- نبضات teal تتحرك على مسارات مختلفة عبر `stroke-dasharray/stroke-dashoffset`، وتضيء نقاط النهاية بالتتابع.
- دورة قريبة من خمس ثوانٍ تتكرر بسلاسة، دون zoom أو تحريك للبطاقة نفسها.

### 2. لوحة الرسائل

- وصف مقترح: `تابع الرسائل والاستخدام وأحداث التسليم من مكان واحد.`
- قائمة رأسية لرسائل معاملات شكلية فوق dotted grid باهتة مع fade أعلى وأسفل.
- تتحرك القائمة خطوة كل نحو ثانيتين. يكبر الصف المركزي قليلًا ويصبح أوضح.
- الحالات المستخدمة فقط من عقد نبضة: `queued → sent → delivered`، أو `failed/expired/cancelled` عند الحاجة.
- badge الانتظار رمادي مع spinner، ثم badge نجاح بلون mint مع check. يجب أن يبقى النص ظاهرًا لأن اللون وحده ليس كافيًا.
- دورة كاملة قرابة عشر ثوانٍ وتعود إلى البداية بلا قفزة مرئية.

### 3. ربط هاتف Android

- وصف مقترح: `اربط هاتف الشركة وشريحتها، ثم اختبر بأمان عبر Mock.`
- browser/device mockup باهت في الخلف، وبطاقة بيضاء واضحة في المقدمة.
- ticker رأسي داخل مساحة مقصوصة يعرض مراحل شكلية مثل: `تم الربط`، `الشريحة جاهزة`، `Mock مفعّل`، `آخر اتصال الآن`.
- العنصر المركزي يكبر قليلًا ويظهر نصه كاملًا، والداخل والخارج يتدرجان إلى الرمادي.
- انتقال كل ثانية تقريبًا لمدة `200–300ms` مع loop متصل.

### 4. Webhooks جاهزة للاستخدام

- وصف مقترح: `أحداث موقعة، إعادة محاولات، وتكاملات تبدأ في دقائق.`
- قائمة تحقق: `توقيع HMAC`، `أحداث الرسائل`، `إعادة المحاولة`.
- tabs صغيرة للحالات `queued / sent / delivered`، مع pill نشطة تتحرك منطقيًا في RTL.
- بطاقة endpoint/event على الطرف المقابل تتغير بـcrossfade بين الحالات كل `1.6–1.8s`.
- لا تعرض الرسمة secret أو payload حقيقيًا؛ تستخدم IDs وعناوين شكلية من نطاق `.invalid`.

## الاستجابة والحركة

المرجع يعرض Desktop بنسبة 4:3 فقط؛ القواعد التالية هي تكييف نبضة المعتمد:

- `>= 1024px`: شبكة `7fr 5fr` بالترتيب غير المتناظر أعلاه.
- `768–1023px`: عمودان متساويان إن سمح المحتوى، وإلا عمود واحد.
- `< 768px`: عمود واحد، العرض `100%`، padding أصغر، وترتيب API ثم لوحة الرسائل ثم Android ثم Webhooks.
- تستخدم العناوين `clamp()`، وتحافظ الرسومات على نسبة داخلية ثابتة بدل الاقتصاص العشوائي.
- توقف الحركات عندما تصبح البطاقة خارج viewport عبر `IntersectionObserver`.
- عند `prefers-reduced-motion: reduce` تظهر حالة ثابتة مفهومة، وتُلغى loops التلقائية.
- لا تعتمد أي وظيفة أو معلومة مهمة على animation.

## مركز المساعدة

ينفذ `/help` بنية توثيق مستقلة مستوحاة من مرجع المستخدم من دون نسخ علامته أو نصوصه:

- شريط علوي ثابت يحمل `Nabda Docs`، بحثًا داخل الأقسام، مؤشر `API v1 · Local`، اختيار اللغة، والمظهر الفاتح/الداكن.
- تنقل جانبي مجمع حسب Get started وMessaging وRecipients وWebhooks وReference، مع شارات طرق HTTP حيث تلزم.
- محتوى مركزي قابل للربط يغطي installation وauthentication وtesting وحقول الطلب والاستجابات والحالات والحصة والطابور وجهات الاتصال والإيقاف والتوقيع والأخطاء والأمان.
- فهرس `On this page` ثابت على سطح المكتب، وتنقل جانبي قابل للفتح على الهاتف.
- أمثلة cURL وNode.js وPython، وأزرار نسخ، وروابط تنزيل OpenAPI وملفي collection/environment المتوافقين مع Postman.
- لا توجد بيانات اعتماد ضمن الصفحة أو ملفات التنزيل، وتستخدم الأمثلة أرقامًا شكلية فقط ووضع Mock محليًا.

المسارات العلوية `/integration`, `/api`, `/webhooks`, `/pricing`, `/help` مستقلة، وCTA يفتح `/get-started`. توحّد الصفحات الهوية والتذييل وحالة العنصر النشط، بينما يحتفظ مركز المساعدة بتخطيطه التقني ذي الأعمدة الثلاثة.

## معايير القبول عند التنفيذ

- مطابقة واضحة لتوزيع المرجع: المساحات، نسب البطاقات، اللون المحايد والحركة الداخلية الهادئة.
- RTL حقيقي باستخدام الخصائص المنطقية، لا مجرد قلب بصري للنص.
- عدم وجود أي اسم أو شعار للمنتج المرجعي أو المزود الخارجي.
- عدم وجود بيانات حقيقية أو ادعاء برسائل غير محدودة.
- الإنجليزية هي المصدر الافتراضي، والعربية لا تختار تلقائيًا إلا إذا حفظ المستخدم تفضيلها.
- كل عنصر في القائمة الرئيسية يفتح صفحة مستقلة، ولا توجد روابط تنقل شكلية بلا وجهة.
- مركز المساعدة قابل للبحث ويعمل على سطح المكتب والهاتف، وتطابق أمثلته عقد API الفعلي.
- أمثلة الرسائل معاملات مصرح بها فقط، ولا توجد لغة تشجع الرسائل الدعائية غير المرغوبة.
- نتيجة ثابتة وجيدة عند تعطيل JavaScript أو تقليل الحركة.
- اختبار Desktop وTablet وMobile، مع فحص contrast والتنقل بلوحة المفاتيح.

هذا المرجع يخص الموقع العام ومركز المساعدة. يمكن للوحة التحكم المحمية إعادة استخدام الألوان والخطوط والمكونات، لكن تخطيطها الوظيفي يُبنى حول الرسائل والأجهزة والاستخدام ولا يُفرض عليه شكل البطاقات التسويقية أو تخطيط التوثيق نفسه.
